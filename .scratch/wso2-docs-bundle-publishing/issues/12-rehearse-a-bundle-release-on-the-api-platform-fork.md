## Question

Does a rough bundle workflow on real content behave as the specs assume? On `tharindulak/docs-api-platform`, cut `release/gateway/1.2.0` from `docusaurus-migration`, and let an inline prototype workflow (only on that branch) run `wso2-docs check` with the converter at a pinned docs-site commit, generate a draft `wso2-docs.yaml` from the 1.2.0 sidebar, pack `api-gateway-1.2.0.docs.zip` with only the files the section uses, attest it and publish a **prerelease** `gateway/v1.2.0` (immutability off). On our side: verify the attestation pinned to workflow and branch, and diff the zip against what the lock builds API Gateway 1.2.0 from. No lock change, no deploy. Afterwards delete branch, release and tag (after the user confirms). Decided with the user 2026-10-27 (Q46 to Q50).
